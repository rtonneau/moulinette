## Review Notes

Checked against the Acceptance Criteria:

- **Opt-in checkbox revealing monitor-ADC dropdown and counts-per-µC field.** `ui/main.slint`'s list-mode settings panel gained a `CheckBox { text: "Enable charge-axis chart"; checked <=> root.charge-axis-enabled; ... }` plus an `if root.charge-axis-enabled:` block with a "Monitor ADC" `ComboBox` (`root.charge-axis-monitor-adcs`/`root.charge-axis-monitor-adc`) and an optional "Counts per µC" `LineEdit` (`root.charge-axis-counts-per-uc`). These are new, dedicated properties — not the Convert screen's `monitor-adcs`/`monitor-adc`/`counts-per-uc` (ticket 08) — because the two pickers resolve against different domains (`.mpa`/histogrammed-`.lst` spectrum-array indices vs. a `.lst` file's own `AdcHeader`s) even though the two screens never show both panels at once; sharing properties across that semantic difference seemed more likely to confuse than to save. `src/gui.rs`'s new `list_monitor_adc_labels(&[AdcHeader])` labels the dropdown ("ADC{n} · {channels} channels", matching ticket 08's `monitor_adc_labels` style for `.mpa`/`Spectrum`), populated/reset whenever a plain `.lst` file loads on Analyze (alongside resetting `charge-axis-enabled` to `false` so a stale selection from a previous file is never carried over).
- **New chart, rendered through the Ticket 6 module, plotting rate against running monitor-ADC count/µC instead of time.** `gui_state::charge_axis_series(file, series, dt_ms, calibration) -> Vec<(String, Vec<(f64, f64)>)>` (new, `src/gui_state.rs`) pairs each ROI's existing `rate_series` bins with `rate::time_binned_rate(&file.events, calibration.monitor_adc, None, 0, None, dt_ms)`'s own per-bin counts, bin-for-bin by index — exactly the fact `time_binned_rate`'s doc comment establishes (same `start_ms`/`dt_ms`/`end_ms: None` always yields the same bin count regardless of which ADC is queried, since the end is resolved from the max `time_ms` over *all* events). Each bin's x-value is an inclusive running sum of the monitor's own bin counts, divided by `counts_per_uc` when calibrated (mirroring `charge_normalized`'s None/Some(cpu) distinction from ticket 08, ADR 0002). `chart::LineChart::rate_vs_charge(series, x_desc)` (new, `src/chart.rs`) is the Ticket 6 module's third constructor, built the same way `rate_vs_time` is (home view from data extent, "Acquisition Rate [Yield/s]" y-axis), differing only in the caller-supplied `x_desc` (`gui_state::charge_axis_label`, new: "Monitor ADC{n} cumulative counts" uncalibrated, "Charge [µC]" calibrated). `src/gui.rs` follows the established `rate_chart`/`violin_chart`/`spectrum_chart` family exactly: a `charge_chart: Option<chart::LineChart>` field on `State`, and `hide_charge_chart`/`show_charge_chart`/`fit_charge_chart`/`hover_charge_chart`/`install_charge_chart` functions wired to a new `InteractiveChart` instance in `ui/main.slint` (reusing Ticket 7's shared component, not a fourth hand-rolled `TouchArea` — the rate-vs-time panel is the only chart that still hand-rolls its own `TouchArea`, and it predates `InteractiveChart`; this ticket's new chart follows the newer, reusable pattern instead). `ListAnalysisOutcome` gained a third `charge_chart: Option<(chart::LineChart, Result<chart::RgbImage, String>)>` field (same shape as `violin_chart`'s, so no tuple/type-complexity issue), computed in the `.lst` analyze worker thread only when `charge_axis_calibration(&ui, &file.adc_headers)` (new; validates the checkbox/dropdown/field through `gui_state::charge_calibration`, reusing ticket 08's validation unchanged) returned `Some`.
- **Existing rate-vs-time chart, CSV and PNG outputs unaffected; purely an additional in-window view.** `list_mode_outputs`/`list_mode_write`/`plot::rate_vs_time`/`plot::write_rate_csv`/`plot::violin` are untouched; the charge-axis chart is computed and rendered alongside them in the worker thread but never passed to any writer. `git diff --stat -- src/plot.rs tests/cli.rs` is empty, confirming no file-output or CLI path was touched. The charge-axis panel in `ui/main.slint` is gated on `root.charge-chart-ready`, set only when the chart actually rendered, exactly like the existing `rate-chart-ready`/`violin-chart-ready` panels.
- **Unit test on a synthetic fixture with a known monitor ADC.** `gui_state::tests::charge_axis_series_pairs_each_bin_with_the_monitors_cumulative_count` reuses the existing `synthetic_lst()` fixture (ADC1 events at channels 25/30/10/99, `t` = 0/100/1200/1300 ms) with `dt_ms = 1000`: two bins, each holding two monitor events, so the independently-computed cumulative count is `[2.0, 4.0]`. The test asserts `charge_axis_series`' x-values equal that expected cumulative sequence exactly (computed via a second, independent call to `rate::time_binned_rate` over the monitor ADC, not by re-deriving the same code path), then separately checks the calibrated (`counts_per_uc: Some(2.0)`) case divides the same cumulative counts, and that the y-values are untouched from `series`' own rates (`2.0`/`0.0`, matching the peak.csv values pinned by `list_mode_run_writes_outputs_and_never_overwrites`).

## Blockers / Challenges

None. One deliberate design call worth flagging for review: the charge-axis monitor-ADC dropdown and counts-per-µC field use new `charge-axis-*` Slint properties rather than reusing the Convert screen's `monitor-adcs`/`monitor-adc`/`counts-per-uc` (ticket 08), even though the two panels are currently mutually exclusive on screen. Reusing them would have saved a few properties but tied two independently-evolving features (a conversion-format picker over `.mpa` spectra vs. an in-window chart picker over `.lst` ADC headers) to one shared piece of state, which seemed like the wrong trade for a few lines of Slint.
